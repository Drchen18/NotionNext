# ChainDesk · 本机双链同币套利

独立的本地 Web 应用：行情首页、设置与钱包、OKX 跨链、交易档案、备忘录。默认模拟模式；模拟行情、模拟资金、模拟哈希均明确标识，不代表实时行情或真实交易。

## 启动

使用 **Node.js 22.23.3 或更高版本**（已在 Node 22.23.3 和 Node 24.19.0 验证），解压后在本目录执行：

```bash
npm ci
npm start
```

也可以运行 `start.sh`（macOS/Linux）或 `start.cmd`（Windows）。首次运行会安装锁定的依赖。服务只监听 `127.0.0.1`，自动由操作系统分配空闲端口；终端显示本机访问地址。关闭终端或 Ctrl+C 停止服务。

启动入口为 `src/start.js`，不依赖 Windows 路径大小写或符号链接匹配。若 npm 启动后没有输出，可在本目录直接执行 `node src/start.js`；应先显示“ChainDesk 正在启动”，随后显示网址或明确的启动错误。

默认数据目录是用户目录下 `.dualchain-arb`，与源代码分开。可用 `ARB_DATA_DIR` 指定其他目录；可用 `PORT` 指定端口，不指定时自动选择。不要在同一数据目录同时启动两个实例。

### Windows 11 安装程序失败时

可以使用官方 ZIP 免安装版，无需运行 MSI，也无需管理员权限：

1. 在“设置 → 系统 → 系统信息”确认系统类型。Intel/AMD 电脑通常选择 [Node 22.23.3 x64 ZIP](https://nodejs.org/dist/v22.23.3/node-v22.23.3-win-x64.zip)，ARM 电脑选择 [ARM64 ZIP](https://nodejs.org/dist/v22.23.3/node-v22.23.3-win-arm64.zip)。
2. 解压 Node ZIP。例如 x64 解压到 `C:\tools\node-v22.23.3-win-x64`，确认该目录直接包含 `node.exe` 和 `npm.cmd`。工具源码解压到 `C:\tools\chain-arb`。
3. 打开 **命令提示符（cmd）**，执行以下命令。若解压到其他位置，替换路径；ARM64 也需替换目录名称：

```bat
set "PATH=C:\tools\node-v22.23.3-win-x64;%PATH%"
node -v
cd /d C:\tools\chain-arb
npm ci
npm start
```

上述 PATH 设置仅对当前窗口有效，每次新开窗口需重新设置。启动后打开终端显示的 `http://127.0.0.1:端口`。Node 22 的 `ExperimentalWarning: SQLite` 是提示，不代表启动失败。如果 `npm ci` 失败，请记录报错文字；这是依赖安装阶段，需要针对具体错误处理。

## 首次使用

逐项填写说明和实际界面截图见 [设置与钱包首次配置指南](docs/首次配置指南.md)。

1. 在模拟模式查看行情、执行一次模拟套利，确认档案中的买入确认、实际数量、卖出和结算顺序。
2. 在设置填写两链同币地址、交易池及 RPC。用户需核对两合约代表同一经济资产；工具不能靠名称证明币的同一性。
3. 两侧分别导入只读地址或签名钱包。BNB 私钥使用 hex；Solana 支持 base58 64 字节私钥、32 字节种子或合法字节数组。加密密码至少 10 字符。
4. 如使用 OKX，填写 **OKX Web3 开发者** API Key、Secret、Passphrase、Project ID。全部在本机密码加密保存。不要把凭据填写进配置文件或聊天。
5. 两侧准备计价币、同币库存，以及配置要求的 BNB/SOL Gas 保留资金。默认计价币为 BNB USDT / Solana USDC；跨链页兑换这两种配置的计价币。
6. 切换实盘，核对“不执行原因”、费用及新鲜报价，手动执行一次后在档案复核；自动套利和自动再平衡需要分别启用。

重启后加密钱包与 OKX 凭据仍保留，需输入各自密码解锁；密码不保存，忘记密码无法恢复私钥。自动化每次启动均关闭。只读钱包可以查询余额和报价，不能签名。

## 行情池与成交支持

- 行情来自 Dexscreener。配置池需被其收录，并以配置套利币为 `baseToken`。价格、池流动性、读取时间、RPC 状态和钱包余额分开呈现。
- **BNB 默认直接交易指定 PancakeSwap V2 池**。池必须是套利币与计价币的直接交易对，且工厂与链上 `getPair` 验证一致；成交包含精确输入、最小输出、接收地址与截止时间。不支持把 V3 池冒充 V2 池。
- **Solana 使用 OKX DEX 聚合交易**，默认严格模式会解析交易及地址查找表，核验指令引用配置池。路由未引用指定池时禁止执行。接口不支持该池或该币时显示原因，不伪造可执行报价。
- BNB 可改用 OKX；默认严格模式需要返回可核验的池信息。OKX 无法提供池证明时，可继续使用 V2 直接池，或者由用户在设置中明确关闭严格池限制，采用聚合路线。可选 DEX ID 限制聚合流动性来源。
- 没有支持任意链、任意池协议的承诺；未支持的协议和不可验证报价会拒绝执行。行情池价格不等于成交价，实际净收益使用可执行路线报价。

## 套利执行与结算

```text
新鲜报价及风控 → 买入准备 → 授权（BNB，如需）
→ 广播买入 → 链上确认 → 回执复核实际到账
→ 按实际数量重新报价 → 卖出风控检查
→ 广播卖出 → 链上确认 → 实际费用与利润结算
```

高价链卖出的是其**预存同币库存**；低价链收到的代币不会瞬间出现在另一链。两链精度不同时用 BigInt 转换数量，无法卖出的最小单位余量记入档案。买入回执没有到账或未确认，禁止卖出。确认后的报价不再满足利润、滑点、库存或费用条件时，也会暂停并保留单边仓位供人工核对。

单次套利是 1–10U（按读取到的计价币美元价格换算输入量）。风控包括净利润门槛、每腿滑点、价格冲击、BNB 总 Gas（含授权）、SOL 网络费、Gas 保留、报价有效期、执行次数与累计套利 U。次数和额度在任务开始时预留，失败不会退回预算来绕过限制。模拟与实盘的额度分别持久化。

BNB 按配置确认数验证回执与规范区块；Solana 等待 finalized。BNB 授权仅批准需要的数量，需要时先清零。广播前还会检查新鲜度、预算和余额；Solana 执行链上模拟并检查含租金后的 Gas 保留。

实际数量来自 ERC20 Transfer 日志及 Solana 回执的 pre/post token balances；网络费来自链上回执，SOL 原生余额变化扣除网络费后记录为净租金/原生支出。美元计价使用存档价格快照，USD 结果不是跨链原子套利的保证。钱包发生外部并发交易、非标准余额变动代币或报价数据缺失时，复核可能拒绝结算并暂停。

每笔档案保存配置、报价、预期哈希、广播/确认状态、授权与兑换回执、实际到账、费用、租金、滑点、实际利润、估算差异和失败原因。可导出 JSON。幂等键防止同一请求重复启动；哈希在广播前持久化。

重启遇到未结算任务会标为“待核对”，**不自动重发、不自动补卖**。在档案读取链上回执，核对两侧余额、哈希及仓位，填写处理说明后人工接管，再解除暂停。人工接管不把失败任务伪标成成功。

## OKX 跨链与再平衡

手动在 BNB Chain 与 Solana 两侧配置的计价币之间兑换。输入的是源链计价币数量，报价另按美元价格计算磨损。**无单次和每日跨链金额上限**，但强制检查源余额、两侧 Gas 保留、价格冲击、最大美元磨损和最大磨损率。原生 BNB/SOL 留作 Gas，不作为默认跨链兑换资产。

自动再平衡仅一侧可用稳定币美元价值低于 5U 时触发。按预计目标净到账迭代求解，使不足侧约为 60%、另一侧约为 40%；两侧最终都必须至少 5U。两侧都低于 5U 或总额不足时不在两链之间往返转移。冷却期默认 60 分钟，未完成跨链始终互斥锁定资金操作。

源链交易确认不等于跨链完成。程序查询 OKX 桥状态并独立读取目标链最终回执，必须核验目标钱包的实际到账。目标哈希缺失、超时、路线不支持、实际磨损超限时暂停并提示人工核对。

报价/构建接口按 OKX 官方 SDK 的 v6 DEX 与 v5 cross-chain 参数实现；API 返回结构不满足验证条件时拒绝成交，不猜测成功。相关依据：<https://github.com/okx/okx-dex-sdk>（开发时参考提交 `6be0a98ae467a942795b7576b373ff912f20bb82`）。

## 本地安全与数据

- 私钥及 OKX 凭据使用 scrypt（N=32768）派生密钥和 AES-256-GCM 加密；随机 salt/IV。数据库与目录限制权限。
- 页面与接口仅返回钱包地址、类型和解锁状态，不返回私钥、密码、密文或 OKX 凭据。填写凭据的输入框隐藏字符，提交后清空。
- 会话 cookie 为 HttpOnly/SameSite=Strict；写接口要求 CSRF token，并检查 Host、Origin、本机来源。页面有 CSP，日志和异常不输出 SDK 请求或凭据。
- SQLite WAL + FULL 同步保存任务和状态事件；备忘录自动记录创建时间，每页 8 条，交易每页 10 条。
- 解锁签名密钥存在当前进程内存中；锁定或退出清除引用，不宣称能抵抗已控制本机的攻击者。备份 `.dualchain-arb` 目录时同时保护其本机访问权限。
- 两侧不共享私钥；本应用不传送私钥到 RPC 或 OKX，只广播本机签名的交易。

需要网络访问 npm（安装）、配置的 RPC、`api.dexscreener.com`、`web3.okx.com`。如系统使用网络代理，Node 24 可用 `NODE_USE_ENV_PROXY=1`；保留受信任 CA，不关闭 TLS 验证。

## 验证与当前边界

```bash
npm test
```

测试覆盖状态机、未确认禁止卖出、单边失败暂停、预算/库存限制、再平衡净到账比例与冷却、私钥加密/重启、回执数量与费用复核、RPC 轮换/网络校验、指定池验证，以及 HTTP 会话/CSRF/幂等性/备忘录分页。

开发验证使用模拟资金和受控协议回执；没有提供真实私钥或 OKX 凭据，也没有广播真实主网交易。**实盘路线、OKX 对账户的授权以及指定币对的跨链可用性，需在本机填写配置后继续验证**。应用会将未通过的条件显示为“不执行原因”；不能把模拟通过当成主网已验证。
